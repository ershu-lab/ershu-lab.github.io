On this page

Read documents, search the project, and ask questions ​

After an analysis, Ershu offers three ways to understand the project. Docs supports structured reading, Search helps locate specific material, and chat on the Docs page can assemble an answer from multiple cited results. They share project permissions but are not the same kind of query.

Confirm that the run produced content ​

Open the latest full-project run from the project's Runs page. Its state should be completed or completed_with_warnings, and its detail should list the documents that were actually produced.

If the run failed, was cancelled, or produced no documents, address its warnings and Worker errors first. Reloading an empty Docs page cannot create missing content.

Read generated documents ​

  1. Open the project's Docs page.
  2. Select a document from the left navigation. Documents are grouped by repository and category, so choose the intended repository in a multi-repository project.
  3. Move through the document with its headings or the on-page table of contents.
  4. Select a source citation to open its source preview.

A successful selection shows the complete document in the main area. The active section follows your reading position. A valid citation opens its repository, path, available line numbers, and source excerpt. Citations let you return to evidence; generated prose is not a substitute for checking that evidence.

Internal document links move between Ershu documents. External links ask for confirmation first. Mermaid diagrams can be opened in a larger view.

Search the project ​

Open the project's Search page, enter a query, and select a mode:

  • Keyword searches by the words you enter and is useful for function names, setting names, and error text.
  • Semantic searches by meaning and requires a usable embedding channel and semantic index.
  • Hybrid combines semantic and keyword results. When semantic capability is unavailable, it can explicitly fall back to keyword results.

The current page offers one optional repository filter. Search all repositories or select one repository. It does not currently offer branch, language, path, or content-type filters, so do not look for controls described by older material.

After submitting, a successful result set shows:

  • the number of returned items;
  • content excerpts;
  • result types such as code, documentation, API, README, or configuration;
  • source paths and available line numbers; and
  • language, document, or section details after expansion when those fields exist.

Select a result card to expand its full excerpt. The current card does not automatically open Docs or transfer the result into chat.

Understand search degradation ​

  • Unavailable semantic search must not silently pretend to be keyword search. Check the embedding channel and the run's search-index status.
  • Hybrid search can fall back to keyword results. The page shows a degradation notice when the result did not use full semantic capability.
  • When keyword search returns nothing, try a more distinctive symbol, setting name, or error string, and confirm that the repository filter is not excluding the source.

Ask a project-scoped question from Docs ​

Chat is available from the Docs page. Open the chat panel and ask a question that the project's source or documents can verify, such as, “How does this project load its configuration?”

The current chat scope is always the whole project:

  • it is not limited to the document currently open;
  • it is not limited to the current section; and
  • in a multi-repository project, an answer can cite more than one repository.

After sending, the panel adds the user message and progressively fills the response from a stream. A successful answer contains text and any available citations. Select a citation to open the same kind of source preview used by document citations.

You can also:

  • start a new session;
  • reopen an existing session;
  • search sessions by title; and
  • delete a session you no longer need.

If the answer reports retrieval-only output or no context, first confirm that the project has searchable content, then check the available model channel. Do not treat an answer without traceable project evidence as a verified conclusion.
