Set up local development ​

Ershu components are maintained independently. When changing one component, install, test, and build it in its own repository. Use the ershu deployment repository when you need shared infrastructure and a pinned backend composition for integration work.

What to install ​

  • Python 3.14 and UV.
  • Node.js 24 and npm.
  • Docker with Compose v2.
  • Git.
  • The Ershu repositories involved in the change.

Keep repositories as siblings:

text
workspace/
├── ershu/
├── ershu-core/
├── ershu-api/
├── ershu-worker/
├── ershu-mcp/
├── frontend/
└── ershu-docs/

They are not one monorepo. Each directory has its own version, lock file, tests, and release. Do not commit changes for one repository from another repository.

Work on one backend component ​

Enter the target repository and install from its lock file:

RepositoryInstallMinimum check
ershu-coreuv sync --lockeduv run pytest -m "not integration"
ershu-apiuv sync --locked --extra devuv run --extra dev pytest -q
ershu-workeruv sync --locked --extra devuv run pytest -q
ershu-mcpuv sync --lockeduv run pytest -q

API, Worker, and MCP declare the Core version ranges they support, while each lock file records the version selected for that development environment. When a Core change affects public behavior, test the affected consumers too. Matching component version numbers are not a compatibility test.

Start shared infrastructure ​

Copy the examples in the ershu deployment repository:

bash
cp .env.compose.example .env.compose
cp .env.example .env
1
2

Replace passwords and secrets in both files, then start the infrastructure:

bash
docker compose --env-file .env.compose -f compose.infrastructure.yml up -d
docker compose --env-file .env.compose -f compose.infrastructure.yml ps
1
2

Inspect a service when needed:

bash
docker compose --env-file .env.compose -f compose.infrastructure.yml logs --tail=200 <service-name>
1

This starts PostgreSQL, Redis, Milvus, etcd, and MinIO. Stop the containers without deleting their data when development ends:

bash
docker compose --env-file .env.compose -f compose.infrastructure.yml down
1

Start the frontend ​

In the frontend repository:

bash
cp .env.example .env.local
npm ci
npm run dev
1
2
3

The Chinese entry point is http://localhost:3000/#/zh, and English is http://localhost:3000/#/en. The development proxy sends /api to API on port 8000 and /mcp to MCP on port 8001 by default.

What a useful local environment looks like ​

Check in order:

  1. PostgreSQL, Redis, and Milvus pass their Compose health checks.
  2. ershu-db current matches ershu-db heads.
  3. API and MCP return ok from /health.
  4. The frontend opens the administrator setup or sign-in page.
  5. An administrator can create and test model channels.
  6. The Worker claims a full-project run instead of leaving it in queued.
  7. After the run, the wiki opens, source search works, and citations lead back to repositories.

Stop at the first failed layer. If API is live but a run does not move, inspect Worker first. If document generation fails, check the language-model channel. If semantic retrieval fails, check Milvus, the embedding channel, and the search-index status.
