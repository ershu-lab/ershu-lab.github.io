Environment variable reference ​

This page records the public configuration read by the current source. A table “default” is the code default, not a production recommendation. change-me, an empty string, and replace-me from .env.example are not usable secrets.

Backend processes read .env, with a process environment value taking precedence over the same value in the file. The frontend uses Vite environment files. Backend settings ignore unknown fields. This allows the bundle to provide one superset file, but it also means a misspelled field may not fail at startup.

A † after a variable means the database can override it through runtime.<lowercase_field_name>. The API refreshes its runtime settings at startup and about every 30 seconds. The Worker refreshes while polling and claiming work. MCP refreshes shared Core runtime settings during an authenticated request. Without a database value, the process environment or .env value applies.

Four common mistakes ​

  1. Secret placeholders in .env.example are not runnable defaults. API and MCP reject weak secrets, and Worker rejects a weak ENCRYPTION_KEY.
  2. Model channels are not environment variables. Administrators save LLM, embedding, and reranker channels through the web interface or API.
  3. Database runtime overrides apply only to variables marked †. Database addresses, secrets, cookies, CORS, and MCP transport-security boundaries remain deployment environment settings.
  4. Runtime changes are not retroactive rewrites. Most values affect new polls, sessions, scans, containers, or index batches; they do not reconfigure work already in progress.
