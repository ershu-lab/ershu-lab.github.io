The hardest part rarely lives in one file ​

Complex projects hide their difficulty between repositories: which endpoint a page calls, which service an endpoint depends on, and why one setting changes an entire workflow. New contributors search repeatedly, maintainers explain the same boundaries, and development agents rebuild context for every task.

Work with coding agents

Give an agent project context, not merely a directory

Reliable context for development agents

Do not push more code into AI. Let it retrieve relevant, version-aware, verifiable project context when it needs it.

Ershu makes project documents, code search, relationships, and source locations reusable through the web app, API, and MCP. This can reduce repeated reading and irrelevant context. Actual token use depends on the project, task, and model and should be measured on real workloads.

Designed for private enterprise code ​

The value of self-hosting is not only where a service runs. It is also the ability to decide who can access each project, how code may be read, and which model services are used.

Self-hosted

Deployment defines the data boundary

The operator manages services, repository credentials, and storage on infrastructure it controls.

Read-only analysis

Understand code without running repository scripts

The Worker extracts project facts with restricted read-only workspace tools and limits paths, file sizes, and tool budgets.

Permission boundaries

Authorize members and agents separately

Project membership protects the web app, while MCP keys can further restrict projects and tool scopes.

Model choice

Configure model channels for your environment

Administrators manage LLM, embedding, and reranker channels without putting model secrets in the frontend.

Self-hosting gives an organization a starting point for controlling its data boundary. Whether code leaves the private network still depends on the model services, network, and logging policy you configure.

Who is Ershu for? ​

01

Products delivered from multiple repositories

Frontend, backend, services, shared libraries, and infrastructure are maintained separately but need to be understood as one project.

02

Unfamiliar or long-lived codebases

Reliable documentation is missing, critical knowledge is concentrated in a few people, and the team needs a shared view rebuilt from current source.

03

Teams bringing AI into development

Development agents need permission-aware project context with traceable sources instead of reading every repository from scratch.
