Vibe coding got faster. Understanding the system did not. ​

AI can complete the code in front of it, but it may not know which service a page depends on, how a change crosses repository boundaries, or whether an old design note is still true. As a project grows, that missing context can erase the speed gained from code generation.

Context resets

Every task starts with reading the project again

Developers and agents keep rediscovering entry points, settings, and call paths. The same understanding work gets paid for repeatedly.

Repository blind spots

You opened one repository, but you are changing a product

Frontend code, APIs, messages, and schemas live apart. The current directory rarely shows the complete impact of a change.

Documentation drifts

The wiki has an answer, but nobody knows if it is current

Once prose falls behind the code, people go back to the maintainer and AI may treat an old explanation as a present fact.

Knowledge bottlenecks

A few maintainers become the project search engine

New hires, QA, product, and support teams keep asking the same questions about boundaries, workflows, and past decisions.

What Ershu does

It turns knowledge scattered across repositories and maintainers into shared context that can be searched, checked, and refreshed.

Ershu prepares the structure, documentation, relationships, and sources before a change begins. People and agents can make fewer guesses and verify their conclusions, while the team still decides how the code should change.

Beyond the wiki: search, relationships, contracts, and refresh ​

Search

Search exact names when you know them, or meaning when you do not

Keyword, semantic, and hybrid modes cover code and documents. Responses make semantic fallback visible.

Relationships

Follow one entry point toward a cross-repository impact area

The project graph, change-surface queries, and static runtime paths help narrow candidates before source review.

Contracts

Pull service agreements out of the codebase

Extract interface facts from sources such as OpenAPI, GraphQL, Protobuf, message channels, and data schemas.

Refresh

Update project facts when the code changes

After the first full baseline, manual runs, scheduled polling, or signed webhooks can refresh trees, indexes, and relationships.

One analysis, two ways to use it ​

The web app is for browsing projects, reading the wiki, searching, exploring the graph, and following analysis runs. MCP lets a coding agent discover a project, then read documents, repository trees, symbols, relationships, and bounded sections of source. Both paths use the same stored results and project permissions.

Where it fits, and where it does not ​

Ershu is most useful when several repositories ship one product, the organization needs control over code and model access, and AI-assisted development is becoming everyday work. It also suits teams taking over a long-lived system or rebuilding missing project documentation.

Know these boundaries before you deploy it:

  • Ershu is self-hosted software, not a hosted code-scanning service.
  • The first analysis covers every active repository in a project. Repository-specific and incremental runs come after that baseline.
  • Generated documents help with navigation and understanding. When they conflict with current source or tests, the source wins.
  • Self-hosting does not guarantee that code stays on a private network. Model requests go to the model services you configure.
  • The Worker does not execute arbitrary repository scripts. Optional LSP support is off by default and requires a separate review of Docker access and dependency sources.
