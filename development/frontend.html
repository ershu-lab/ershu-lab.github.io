开发前端 ​

Ershu 前端是独立仓库。它负责浏览器界面、浏览器状态和 HTTP 请求，不导入 Core、API、Worker 或 MCP 的源码。修改页面前，应先通过正在运行的 Ershu 和已发布接口确认约定，不能用本机恰好存在的后端目录补出隐含依赖。

技术与运行边界 ​

当前前端使用：

  • Node.js 24；
  • Vite 7；
  • React 19；
  • React Router 的 Hash 路由；
  • TypeScript；
  • Tailwind CSS 和 Radix 组件；
  • markdown-it、Mermaid 和知识图谱组件。

Hash 路由让静态文件可以承载运行时页面。中文页面地址形如 #/zh/projects，英文页面形如 #/en/projects。

前端只知道公开 HTTP 约定。后台队列、权限判断、文档生成和搜索实现仍由后端负责；界面不能把本地推测当成服务端事实。

目录职责 ​

路径作用
src/app.tsx路由、登录保护、项目布局和全局提供器
src/pages/与路由对应的轻量页面入口
src/features/页面控制器、视图和可单独测试的状态逻辑
lib/api/请求方法、请求和响应类型、Cookie 与 CSRF 处理
lib/api-client.ts汇总各组 API 客户端
lib/auth-context.tsx登录状态、会话恢复、刷新和退出
lib/i18n.ts中文和英文消息读取与路径语言解析
messages/zh.json、messages/en.json两种语言的界面文字
lib/theme-provider.tsx亮色、暗色和跟随系统主题
components/通用布局和界面组件
hooks/事件流和通用交互钩子

新增功能时，优先把请求放在 lib/api/，把可复用状态放在 src/features/，让 src/pages/ 只负责组合。这样页面入口不会同时承担请求、状态、渲染和文案。

启动本地前端 ​

在独立的 frontend 仓库中执行：

bash
cp .env.example .env.local
npm ci
npm run dev

开发服务器默认监听 http://localhost:3000。成功后，终端中的开发进程应保持运行，浏览器访问该地址会进入首次管理员设置、登录或项目列表中的一个，而不是显示静态空白页。

本地构建变量只有四项：

变量默认值作用
VITE_API_BASE_URL/api/v1浏览器请求的 API 基础路径
VITE_CSRF_COOKIE_NAMEershu_csrfCSRF Cookie 名称
VITE_DEV_API_PROXYhttp://localhost:8000开发环境的 API 代理目标
VITE_DEV_MCP_PROXYhttp://127.0.0.1:8001开发环境的 MCP 代理目标

修改代理目标后要重启开发服务器。模型名称、模型 API Key 和模型通道地址不属于这些构建变量，它们由管理员在网页后台配置。

新增或修改一个页面 ​

1. 先确认接口约定 ​

通过运行中的 Ershu MCP、接口文档和实际响应确认：

  • 路径和请求方法；
  • 请求和响应字段；
  • 权限要求；
  • 失败状态；
  • 长任务是否使用快照、事件流或最终结果。

确认完成后，你应能指出界面每个字段来自哪个公开响应，而不是引用后端内部对象。

2. 扩展 API 客户端 ​

在 lib/api/ 对应模块中增加请求和类型，并从客户端入口导出。请求应继续使用已有的公共请求层，以保持 Cookie、CSRF、错误解析和刷新行为一致。

如果请求提交密码、Token、SSH 密钥或模型 API Key，还要沿用安全传输检查。本机地址可以用于开发，其他主机名必须使用 HTTPS。

完成后，请求方法应能由功能代码导入，且没有页面直接拼接另一个 API 基础地址。

3. 把状态和视图放进功能目录 ​

在 src/features/<feature>/ 中拆分：

  • 负责加载和提交的控制器；
  • 负责展示的视图；
  • 不依赖浏览器的状态转换和辅助函数；
  • 对这些纯逻辑的测试。

完成后，状态切换、权限显示和失败处理应能在不复制页面组件的情况下被检查。

4. 接入页面和路由 ​

在 src/pages/ 添加轻量入口，再在 src/app.tsx 中使用延迟加载接入路由。项目内页面放在 /:locale/projects/:projectId 下；全局管理页面放在现有工作区结构下。

成功后，中英文地址都能进入同一页面，并且未登录用户仍会回到对应语言的登录页。

5. 同步中英文文字 ​

在 messages/zh.json 和 messages/en.json 添加相同结构的消息键。不要在组件中写只属于一种语言的提示，也不要让错误回退提示只显示英文。

切换语言后，当前页面路径和对象编号应保持不变，只替换语言段和界面文字。

6. 保持现有长任务语义 ​

运行详情必须区分活动状态和终止状态：

  • 活动运行先读取快照，再从游标之后连接事件流；
  • completed 和 completed_with_warnings 直接读取最终结果；
  • failed 和 cancelled 不应继续连接事件流；
  • 刷新页面不能创建新的运行。

Docs 中的聊天当前是项目范围。不要因为用户正在阅读某篇文档，就在请求中声称聊天已经变成文档或章节范围。

验证改动 ​

提交前按顺序运行：

bash
npm test
npm run lint
npm run format:check
npm run build

2
3
4

判定标准：

  • npm test 以退出码 0 结束；
  • npm run lint 同时通过代码检查和 TypeScript 检查；
  • npm run format:check 没有列出需要重新排版的文件；
  • npm run build 以退出码 0 结束，并生成 dist/。

当前自动测试主要覆盖状态逻辑、请求约定和事件处理，不是完整的浏览器端到端测试。还需要手工检查：

  • 中文和英文路由；
  • 亮色、暗色和跟随系统主题；
  • 375 像素左右的窄屏和常见桌面宽度；
  • 键盘操作和焦点；
  • 登录失效、请求失败和空数据；
  • 活动运行刷新与完成态加载。

如果某项检查失败，请按开发故障排查定位原因，不要通过删除测试或放宽接口类型来掩盖问题。
