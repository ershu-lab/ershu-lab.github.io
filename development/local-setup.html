搭建本地开发环境 ​

当前完整开发环境面向能够访问 Ershu 私有组件源的维护者。后端安装清单锁定了私有 Git 地址，因此仅克隆公开组合仓库还不能完成安装。不要用未经固定的本地兄弟目录替换锁定依赖。

前置条件 ​

  • Python 3.14 或更高版本；
  • UV，用于安装和运行 Python 项目；
  • Node.js 24 与 npm，用于前端；
  • Docker 与 Docker Compose，用于 PostgreSQL、Redis 和 Milvus；
  • 能读取锁文件中 Ershu 组件源的 SSH 凭据；
  • 五个模块和 ershu 组合仓库的匹配提交。

用组合仓库启动完整后端 ​

以下命令在 ershu 目录中的 Bash shell 运行；复制后必须替换所有安全占位值。

bash
cp .env.compose.example .env.compose
cp .env.example .env
1
2

.env.compose 为 PostgreSQL 与 MinIO 提供凭据。.env 为后端进程提供数据库、Redis、Milvus、会话、加密、MCP 和 Worker 设置。示例中的 replace-me、固定弱口令和空生产必填项都不能直接使用。

启动基础设施：

bash
docker compose --env-file .env.compose up -d
docker compose --env-file .env.compose ps
1
2

成功时，PostgreSQL、Redis、Milvus、etcd 和 MinIO 容器会启动；带健康检查的服务最终应显示为健康。若基础设施未就绪，先查看 docker compose --env-file .env.compose logs，不要继续迁移。

bash

uv run ershu-db upgrade head

API 默认监听 127.0.0.1:8000，MCP 默认监听 127.0.0.1:8001。用下面的存活检查确认两个 HTTP 进程已经响应：

curl -fsS http://127.0.0.1:8000/health

两者都应返回 status 为 ok。这只证明进程存活，不证明数据库、Milvus、模型通道或 Worker 已完成业务就绪。

启动前端 ​

在独立的 frontend 目录运行：

bash
cp .env.example .env.local
npm ci
npm run dev
1
2
3

开发服务器默认位于 http://localhost:3000，并把 /api 代理到 http://localhost:8000，把 /mcp 代理到 http://127.0.0.1:8001。服务地址不同时，只修改 .env.local 中对应的开发代理变量。

首次打开 http://localhost:3000/#/zh/setup-admin。没有用户时会进入首位管理员设置；创建成功后进入登录或项目界面。Ershu 不开放自助公开注册，后续账号由管理员创建。

单独开发一个后端模块 ​

在目标仓库按锁文件安装，不把其他模块源码临时塞进导入路径：

模块安装命令最小验证
Coreuv sync --frozenuv run pytest -m "not integration"
APIuv sync --extra dev --frozenuv run --extra dev pytest -q
Workeruv sync --extra dev --frozenuv run pytest -q
MCPuv sync --frozenuv run pytest -q

Core、API、Worker 和 MCP 的锁文件固定了相互匹配的 Core 提交。修改 Core 后，应先提交并更新消费仓库的依赖与锁文件，再做跨仓验收。

确认环境真的可用 ​

按由近到远的顺序检查：

  1. 基础设施容器健康，数据库升级到当前 head；
  2. API 和 MCP 存活地址返回 ok；
  3. 前端能打开，并完成首位管理员流程；
  4. 管理员能创建并测试模型通道；
  5. 能添加一个测试仓库并通过仓库验证；
  6. 创建全项目运行后，状态从排队进入运行，最终得到明确结果；
  7. 完成后能打开文档，并取得带来源位置的搜索结果。

某一步失败时停止向后排查。进程存活但运行一直排队，首先确认 Worker；文档阶段失败，先确认模型通道；语义检索失败，先确认 Milvus 与嵌入设置。

事实来源：六个仓库的安装清单、锁文件、README、进程入口、Compose 文件、健康路由和持续集成配置。
