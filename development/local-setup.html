搭建本地开发环境 ​

Ershu 的组件分别维护。只改一个组件时，直接在它自己的仓库安装、测试和构建；需要完整联调时，再用 ershu 部署仓启动固定版本的后端组合和基础设施。

需要安装什么 ​

  • Python 3.14 与 UV；
  • Node.js 24 与 npm；
  • Docker 与 Compose v2；
  • Git；
  • 需要联调的 Ershu 仓库。

推荐把仓库放成平级目录：

text
workspace/
├── ershu/
├── ershu-core/
├── ershu-api/
├── ershu-worker/
├── ershu-mcp/
├── frontend/
└── ershu-docs/

它们不是一个总仓库。每个目录有自己的版本、锁文件、测试和发布流程，不要在一个仓库里提交另一个仓库的改动。

只开发一个后端组件 ​

进入目标仓库，按它自己的锁文件安装：

仓库安装最小检查
ershu-coreuv sync --lockeduv run pytest -m "not integration"
ershu-apiuv sync --locked --extra devuv run --extra dev pytest -q
ershu-workeruv sync --locked --extra devuv run pytest -q
ershu-mcpuv sync --lockeduv run pytest -q

API、Worker 和 MCP 声明自己能够接受的 Core 版本范围，但锁文件会记录当前开发环境实际解析到的版本。改动 Core 公共能力时，要同时检查受影响组件；不要用版本号是否相同来判断兼容性。

启动共享基础设施 ​

在 ershu 部署仓复制配置：

bash
cp .env.compose.example .env.compose
cp .env.example .env
1
2

替换两份文件中的密码和密钥，再启动基础设施：

bash
docker compose --env-file .env.compose -f compose.infrastructure.yml up -d
docker compose --env-file .env.compose -f compose.infrastructure.yml ps
1
2

需要看日志时：

bash
docker compose --env-file .env.compose -f compose.infrastructure.yml logs --tail=200 <service-name>
1

这组服务提供 PostgreSQL、Redis、Milvus、etcd 和 MinIO。开发结束后可以停止容器而保留数据：

bash
docker compose --env-file .env.compose -f compose.infrastructure.yml down
1

启动一套固定版本的后端 ​

在已经发布的部署标签中运行：

bash
uv sync --locked --extra all
uv run --locked --extra all ershu-db upgrade head
1
2

然后分别启动：

bash
# 终端 A
uv run --locked --extra all ershu-api

# 终端 B
uv run --locked --extra all ershu-worker

# 终端 C
uv run --locked --extra all ershu-mcp

# 终端 D，只有需要计划轮询时才启动
uv run --locked --extra all ershu-api-poller

启动前端 ​

在 frontend 仓库运行：

bash
cp .env.example .env.local
npm ci
npm run dev
1
2
3

中文入口是 http://localhost:3000/#/zh，英文入口是 http://localhost:3000/#/en。默认开发代理把 /api 发往 API 的 8000 端口，把 /mcp 发往 MCP 的 8001 端口。

本地环境怎样算可用 ​

按顺序检查：

  1. Compose 中的 PostgreSQL、Redis 和 Milvus 通过健康检查。
  2. ershu-db current 与 ershu-db heads 一致。
  3. API 与 MCP 的 /health 返回 ok。
  4. 前端能打开首位管理员设置页或登录页。
  5. 管理员可以创建并测试模型通道。
  6. Worker 能领取一条完整项目运行，状态不再停在 queued。
  7. 运行结束后可以打开 Wiki、搜索源码，并从引用回到仓库。

某一步失败时先停下来修这一层。API 存活但任务不动，先看 Worker；文档生成失败，先看语言模型通道；语义检索失败，先看 Milvus、向量模型通道和搜索索引状态。
