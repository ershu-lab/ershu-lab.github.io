配置后端：先改哪些值 ​

快速部署会把后端配置放在 /etc/ershu/.env，API、Worker、MCP 和数据库命令都从这个目录读取它。安装脚本根据部署仓的 .env.example 创建文件。不要从环境变量参考表重新手写一份。

从源码运行时，仍然把 .env.example 复制为项目工作目录中的 .env。

这一页只说明第一次必须理解的值。所有字段、类型和默认值见环境变量参考。

1. 先配置三个数据服务 ​

服务主要用途相关设置
PostgreSQL账号、项目、权限、任务、文档和系统设置DATABASE_URL 与连接池设置
Redis登录限流和计划轮询的租约协调REDIS_URL
Milvus向量索引和语义检索MILVUS_URI、MILVUS_TOKEN、MILVUS_DB_NAME

API、Worker 和 MCP 必须连接同一个 PostgreSQL。启用向量检索时，三者也应连接同一个 Milvus 数据库。Redis 不保存 Worker 的持久任务队列。

使用部署仓的单机 Compose 时，默认地址已经指向本机。把 /etc/ershu/compose.env 中的 PostgreSQL 密码同步到 /etc/ershu/.env 的 DATABASE_URL。

2. 生成四项长期密钥 ​

部署包提供的脚本会生成 PostgreSQL 与 MinIO 密码、DATABASE_URL 和四项长期密钥：

bash
uv --directory /opt/ershu/current run --no-sync \
  scripts/generate_config_values.py
1
2

把 SECRET_KEY、ENCRYPTION_KEY 和 MCP_KEY_PEPPER 填入 /etc/ershu/.env：

  • SECRET_KEY：保护登录令牌和 CSRF 令牌；
  • ENCRYPTION_KEY：加密保存仓库凭据和模型密钥；
  • MCP_KEY_PEPPER：保护 MCP 密钥摘要。

三个值都不能少于 32 个字符，不能相同，也不能保留 replace-me 一类占位值。更换它们会让现有会话、密文或 MCP 密钥失效，因此生产环境应放进密钥管理系统并长期保存。

同一条命令输出的 OPAQUE_SERVER_SETUP 也要写入该文件。更换后，已有密码记录不能继续使用。生产环境必须明确设置；开发环境可以自动生成并保存，但第一次部署就应固定。

3. 配好浏览器与反向代理 ​

本地开发可以保留：

dotenv
HOST=127.0.0.1
PORT=8000
CORS_ORIGINS=["http://localhost:3000"]
SESSION_COOKIE_SECURE=false
SESSION_COOKIE_SAMESITE=lax
1
2
3
4
5

生产环境需要改为：

  • ENVIRONMENT=production；
  • SESSION_COOKIE_SECURE=true；
  • CORS_ORIGINS 只包含实际前端的 HTTPS 来源；
  • 经过反向代理时开启 PROXY_HEADERS，并让 FORWARDED_ALLOW_IPS 只信任真实代理地址；
  • API 和 MCP 继续监听内网或回环地址，只由 HTTPS 代理对外开放。

浏览器与 API 使用同一个域名最容易配置。跨域部署还要同时处理 CORS、Cookie、来源检查和代理协议，不要只改前端地址。

4. 限制仓库从哪里来 ​

设置建议
REPOSITORY_STORAGE_PATH使用明确、可写、可持久保存的目录
GIT_ALLOWED_HOSTS只列出团队实际使用的 Git 主机
ALLOW_INSECURE_GIT_URLS保持 false
ALLOW_FILE_GIT_URLS保持 false，除非已经评估本地文件协议风险
TRUSTED_LOCAL_PATHS只列出允许 Ershu 读取的本地仓库根目录
ALLOW_DEV_OPEN_LOCAL_REPOSITORY_PATHS生产环境保持 false

浏览器所在机器能看到的本地路径，不一定能被 Worker 或 MCP 所在主机读取。登记本地仓库前，先确认实际进程能访问同一路径。

GitHub 或 GitLab Token 可以作为后备凭据，但更推荐在网页凭据库中按仓库分配 Token 或 SSH 密钥。不要把真实凭据提交到 .env.example。

5. 模型通道不写进 .env ​

语言模型、向量模型和重排模型都在管理后台创建。模型名称、API Key、服务地址和计费设置保存在数据库中，敏感值由 ENCRYPTION_KEY 加密。

生成 Wiki 至少需要一个可用的语言模型通道。语义搜索还需要单独的向量模型通道。没有向量模型时，关键词搜索仍可工作。

6. 启动后怎样确认 ​

快速部署使用 systemd 完成数据库升级并启动后端：

bash
sudo systemctl restart ershu-migrate.service
sudo systemctl start ershu.target
1
2

然后检查：

bash
curl -fsS http://127.0.0.1:8000/health
curl -fsS http://127.0.0.1:8000/api/v1/health/dependencies
1
2

第一个地址只说明 API 进程能响应。第二个地址检查 PostgreSQL 和 Milvus，但不检查 Redis、Worker 或模型通道。完整部署还要确认 Worker 能领取一条真实任务，并实际完成一次登录和模型通道测试。

从源码运行时，请按本地开发环境中的 UV 命令启动各组件。

不知道哪个值覆盖了哪个值时，看配置加载与覆盖。准备上线时，再按权限与安全逐项核对。
