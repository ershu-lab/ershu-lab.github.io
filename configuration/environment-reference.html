环境变量参考 ​

本页记录当前源码实际读取的公开配置。表中的“默认值”是代码默认值，不是生产建议；change-me、空字符串和 .env.example 中的 replace-me 都不能作为真实密钥。

后端使用 .env，进程环境中的同名值优先于 .env。前端使用 Vite 环境文件。未识别的后端字段会被忽略，因此组合仓库可以提供一份配置全集，但拼写错误也可能不会在启动时直接报错。

变量名后的 † 表示该字段还可以由数据库中的 runtime.<小写字段名> 覆盖。API 在启动后每约 30 秒刷新自己的运行时设置；Worker 在轮询和领取任务时刷新；MCP 在认证请求中刷新 Core 共享运行时设置。数据库覆盖不存在时，才使用进程环境或 .env 的值。

最容易配错的四点 ​

  1. .env.example 的密钥占位符不是可运行默认值。API 与 MCP 会拒绝弱密钥，Worker 会拒绝弱 ENCRYPTION_KEY。
  2. 模型通道不通过环境变量配置。管理员应在网页或 API 中保存 LLM、嵌入和重排通道。
  3. 数据库运行时覆盖只作用于带 † 的字段。数据库地址、密钥、Cookie、CORS 和 MCP 传输安全边界仍要通过进程环境部署。
  4. 修改运行时字段也不是追溯改写：多数值只影响新的轮询、会话、扫描、容器或索引批次，已经运行的工作不会被重新配置。
