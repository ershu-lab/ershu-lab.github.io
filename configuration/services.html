按模块配置五个服务 ​

Ershu 由五个独立模块组成。它们共享数据约定，但不是五个都要启动：Core 是共享包，另外四个模块才有运行中的进程或网页。

API、Worker 和 MCP 都只依赖 Core。Worker 与 MCP 不直接调用 API，也不互相调用；它们通过 PostgreSQL 中的项目、任务和索引状态协作。

模块职责和启动边界 ​

模块负责什么快速部署中的入口默认地址可观察的就绪信号
Core设置、数据模型、数据库迁移、权限、仓库访问和共享查询ershu-migrate.service无数据库迁移服务成功结束
API网页登录、项目与仓库管理、运行、文档、搜索、聊天和管理接口ershu-api.service127.0.0.1:8000/health 返回 status: ok；依赖检查见下文
Worker领取任务，准备只读工作区，建立目录、代码索引、关系和搜索索引，并生成文档ershu-worker.service无监听端口进程持续运行；排队任务开始推进
MCP向开发智能体提供受权限约束的只读工具ershu-mcp.service127.0.0.1:8001/mcp/认证后调用 get_server_info，返回版本、构建提交和工具列表
Frontend提供浏览器界面，只通过已发布的 HTTP 接口访问后端Nginx 托管发布包127.0.0.1:8080首次管理员设置页或登录页能够打开，且没有持续网络错误

API 仓库还提供独立的 ershu-api-poller 进程，用于执行仓库的 UTC Cron 计划。它不是 API Web 进程的一部分，也不代替 Worker。

共享值必须保持一致 ​

独立运行各模块时，每个进程从自己的环境读取设置。组合部署可以使用 ershu/.env.example 作为后端配置全集，但每个模块只消费自己认识的字段。

以下值不能在进程之间随意分叉：

  • API、Worker 和 MCP 必须连接同一套 PostgreSQL，任务和项目状态才能互相可见。
  • 需要向量检索时，API、Worker 和 MCP 应连接同一 Milvus 数据库。
  • Worker 的 ENCRYPTION_KEY 必须与写入加密凭据和模型密钥的 API 一致；MCP 读取受保护凭据时也使用同一值。
  • API 与 MCP 的 SECRET_KEY、ENCRYPTION_KEY 和 MCP_KEY_PEPPER 都必须是至少 32 个字符的强值，三者彼此不同；两项服务之间应使用相同的一组值。
  • 模型通道保存在数据库中，由网页管理后台或 API 管理，不写入 .env。

完整字段、默认值和范围见环境变量参考。

仓库工作区怎样分配 ​

远程 Git 仓库不要求 MCP 与 Worker 共用缓存。两个进程都能按登记的远程地址准备自己的只读工作区，REPOSITORY_STORAGE_PATH 可以指向各自主机上的缓存目录。

本地仓库不同：登记的路径不会被复制到另一台主机。Worker 要分析它、MCP 要读取它，这两个进程就都必须能看到同一路径，并且该路径要在 TRUSTED_LOCAL_PATHS 允许范围内。生产环境不能用 ALLOW_DEV_OPEN_LOCAL_REPOSITORY_PATHS 绕过这项限制。

systemd 的启动顺序 ​

快速部署运行 systemctl start ershu.target 后，会按下面的顺序启动：

  1. 启动 PostgreSQL、Redis 和 Milvus 等基础设施。
  2. 用 Core 提供的迁移入口升级数据库。
  3. 启动 API，检查 /api/v1/health/dependencies。响应中的 database.ok 和 milvus.ok 都应为 true。这个检查不包含 Redis。
  4. 启动 Worker，确认它没有因密钥、数据库或结构化解析器自检失败而退出。
  5. 同时启动 MCP，等待需要接入的客户端。
  6. Frontend 由 Nginx 单独托管；Poller 只在启用计划轮询后启动。

API 和 MCP 的 /health 都只是进程存活信号。MCP 是否真正可用，要以带凭据调用 get_server_info 为准；Worker 是否可用，要以任务能被领取和推进为准。

反向代理要分开转发 ​

生产代理应保留原始路径，并将两个前缀发送到不同进程：

路径目标
/api/API 的 8000 端口
/mcp/MCP 的 8001 端口

前端默认使用同源 /api/v1。不要把 /mcp/ 发到 API 端口。代理终止 HTTPS 时，还要把实际的 Host 和 X-Forwarded-Proto 传给后端，并按代理来源设置 FORWARDED_ALLOW_IPS。MCP 的外部域名和来源还要加入 MCP_ALLOWED_HOSTS 与 MCP_ALLOWED_ORIGINS。
