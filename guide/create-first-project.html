创建第一个项目 ​

这一页从首次打开网页开始，直到项目和仓库出现在工作台中。最后会创建第一次运行，但不会在这里假定分析已经完成。

开始前，请确认 API、Worker 和前端都在运行。Worker 是第一次分析的必要进程；只有 API 时，运行会进入队列，但不会真正分析仓库。

第 1 步：创建首位管理员 ​

打开 http://localhost:3000。全新数据库会进入首次管理员设置页。

填写：

  • 邮箱；
  • 可选的显示名称；
  • 至少 8 位的密码；
  • 与密码相同的确认值。

提交后，首位用户会成为系统管理员，并自动进入模型通道页面。若页面直接显示登录表单，说明数据库中已经存在用户；请使用现有账号登录，而不是尝试再次初始化。

第 2 步：准备模型通道 ​

分析运行至少需要一个已启用的大语言模型（LLM）通道。模型通道在网页后台保存，不放在 .env 中。

在模型通道页面创建通道时：

  1. 选择提供方和 llm 能力。
  2. 填写模型名称、API Key，以及提供方需要的地址。
  3. 使用页面提供的连接或模型测试确认配置可用。
  4. 保存并保持通道启用。

成功后，通道会出现在模型通道列表中，并能在新建项目的 LLM 通道选择框中看到。

如果你还要使用语义搜索或混合搜索，再创建一个独立的向量模型（embedding）通道。一个通道只保存一种能力，不能把 LLM 和 embedding 合并成同一条配置。没有 embedding 通道时，不应期待语义索引可用。

密钥传输

本机地址允许提交密码和 API Key。通过其他主机名访问时，前端要求 HTTPS；生产环境不要通过明文 HTTP 提交密钥。

第 3 步：填写项目信息 ​

进入 项目，选择 创建项目。

  1. 填写项目名称。页面会生成标识，你也可以在提交前修改它。
  2. 按需要填写描述。
  3. 选择公开或私有。第一次尝试建议先确认你的权限目标，再决定是否公开。
  4. 选择默认 LLM 通道；如果已经配置 embedding 通道，也可一并选择。

成功的中间状态是：创建按钮可用，项目名称和标识都不是空值，通道选择框中能看到刚才保存的通道。

第 4 步：添加仓库 ​

同一个项目可以包含多个仓库。第一次尝试只添加一个你确定能读取的仓库，便于定位问题。

仓库表单支持：

  • GitHub 仓库 URL；
  • GitLab 仓库 URL；
  • Ershu 服务能够访问的本地路径。

填写仓库名称、类型、URL 或本地路径，以及默认分支。浏览器所在机器能看到某个本地路径，不代表 API 和 Worker 所在机器也能看到它；本地路径必须对实际运行 Ershu 的进程可读。

新建项目表单不收集远程私有仓库的凭据。若仓库需要 Token 或 SSH 密钥，先创建项目，再进入项目的 仓库 页面配置凭据，然后再开始运行。

第 5 步：创建项目并核对结果 ​

选择 创建。成功后，页面会进入新项目的概览。

请核对：

  • 项目名称和描述正确；
  • 项目显示预期的公开或私有状态；
  • 仓库数量正确；
  • 在 仓库 页面能看到刚添加的仓库。

创建项目不会自动开始分析。此时 Docs 和 Search 页面没有新产物是正常情况。

第 6 步：创建第一次运行 ​

确认 Worker 仍在运行，然后进入项目的 运行 页面，选择 新建运行。

第一次分析必须满足两个条件：

  1. 运行类型选择 完整项目（full_project）。
  2. 范围覆盖项目中的全部活动仓库。

在完整项目基线建立前，页面会锁定这个范围。不要改用单仓库或增量运行来绕过基线要求。分支可以留空以使用仓库默认分支；模型和 embedding 通道可以沿用项目默认值。

提交成功后，新运行会出现在列表顶部，初始状态通常是排队中或其他活动状态。这只表示 API 已经接收任务；请继续跟踪第一次分析，直到 Worker 处理完成。
