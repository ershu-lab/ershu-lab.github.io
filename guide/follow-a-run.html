开始并跟踪第一次分析 ​

Ershu 的仓库分析是后台长任务。API 创建运行，Worker 从队列取出任务，前端负责显示当前快照和后续事件。本页说明怎样判断运行真的在推进，以及结束后应检查什么。

开始前检查 ​

第一次运行前应满足：

  • 项目至少有一个活动仓库；
  • 已启用可用的大语言模型（LLM）通道；
  • API 和 Worker 使用同一套数据库配置；
  • Worker 进程正在运行；
  • 私有远程仓库已经配置可用凭据。

如果 Worker 没有运行，API 仍可能成功创建任务，但状态会停留在队列中。

第 1 步：使用完整项目范围 ​

进入项目的 运行 页面，选择 新建运行。

第一次运行选择：

  • 类型：完整项目（full_project）；
  • 仓库范围：全部活动仓库；
  • 分支：留空使用各仓库默认分支，或填写你确定存在的分支；
  • LLM 通道：使用项目默认值或选择另一个已启用通道；
  • embedding 通道：需要语义索引时选择已启用的独立通道；
  • 并行：不确定时保持关闭，此时仓库按并行数 1 处理。

在基线尚未建立时，后端只允许完整项目运行，并要求覆盖全部活动仓库。前端会显示基线提示并锁定仓库范围。

选择 新建运行 后，新记录会出现在列表顶部。看到 queued、running、scanning、analyzing 或 finalizing 中的任一状态，说明运行仍是活动状态。

第 2 步：确认 Worker 正在推进任务 ​

运行列表在存在活动任务时每隔约 5 秒刷新。打开运行详情，可以看到已经持久化的快照、时间线、分析块、工具调用和用量信息；具体内容取决于任务当前阶段。

如果状态长时间停在 queued：

  1. 检查 Worker 终端是否仍在运行。
  2. 确认 Worker 和 API 读取同一份数据库及相关密钥配置。
  3. 查看 Worker 的当前错误，而不是反复创建新运行。

成功的中间结果是状态从 queued 继续进入扫描、分析或收尾阶段，详情页也开始出现新的时间线内容。

第 3 步：安全刷新页面 ​

活动运行首次打开时，前端读取当前快照，再从快照游标之后接收事件。你可以刷新浏览器或稍后重新打开同一个运行，不需要从最早的输出重新播放。

刷新成功后，你应看到：

  • 同一个运行编号；
  • 已经保存的分析内容；
  • 从当前游标继续出现的新事件，而不是重新创建一个任务。

不要把浏览器事件流当作任务本身。关闭页面不会取消 Worker 中的运行。

第 4 步：判断是否完成 ​

终止状态包括：

  • completed：运行完成；
  • completed_with_warnings：运行完成，但有需要检查的警告；
  • failed：运行失败；
  • cancelled：运行已取消。

完成或带警告完成后，前端直接读取最终结果，不再保持事件流连接。详情页应能显示最终过程文本、分析块、用量、警告和本次生成的文档。

完成后请核对：

  1. 运行状态是 completed 或 completed_with_warnings。
  2. 详情页显示最终结果，而不是持续等待新事件。
  3. 生成文档区域至少列出本次实际产出的文档。
  4. 搜索索引状态符合预期；如果是 degraded 或 unavailable，先阅读警告，不要把它描述成完整语义索引。

completed_with_warnings 不是无条件成功。可以继续使用已经生成的结果，但应先确认哪些仓库、文档或索引没有完整生成。

取消和重试 ​

有项目管理权限的用户可以取消活动运行。取消请求完成后，状态会变为 cancelled；页面关闭本身不会取消任务。

终止状态的运行可以通过页面的重试操作创建新运行。重试后会出现新的运行记录，请跟踪新记录，不要等待旧记录恢复为活动状态。

当文档已经生成后，继续阅读文档、搜索项目和发起问答。
